# 2.5.27 — durable event capture before transmission

- Save each time-synchronized event to the existing persistent background outbox before waiting for an earlier network request or issuing its own HTTP request.
- Keep the original event key, captured server-clock timestamp and signed employee session through navigation, offline recovery and restart. Never retime older events as fresh presence.
- Delete the durable copy only after server acceptance. Archive explicit terminal break authorization failures before their existing conservative fallback; failed/unsent evidence is not silently discarded.
- Immediate delivery and outbox replay share one network owner per event. Cache accepted acknowledgments for up to five minutes, bounded to 256 entries, with no cached Date sample used for clock calibration.
- ACK/rejection operations are scoped to the original employee token and event key. Outbox/ACK races cannot produce duplicate rejection-review counters.
- Preserve 2.5.26 native SSE fallback, break readiness, break policy and login/logout. Break request and native agent hook assets are unchanged. No new polling timer or host permission.
- On the native Queue Real Time report only, passively capture its successful XHR responses and suppress duplicate collector live requests while those responses are fresh. Capture every changed reply immediately (the native report polls at 1 Hz); do not throttle changes to five seconds. Ignore duration-only ticks/row reordering, with a ten-second unchanged refresh. Resume fallback fetching after 15 seconds without a valid native reply. Invalid responses and stopped collectors cannot activate passive suppression.
- Native request sequence/page IDs reject older out-of-order responses. Save changed snapshots in a dedicated persistent outbox before upload; retain original clock evidence through restart and bounded-backoff retries. One HTTP upload owner. Queue capacity is 256 records / 4 MB with an explicit failure instead of silent eviction. Older collector bindings are never uploaded under a new binding.
- Add a separate append-only server capture table. Duplicate IDs cannot overwrite evidence or refresh live state; late/unverified snapshots are archival only, not fresh live data or employee work events. Unchanged refreshes do not grow the journal. No existing users, history or call events are migrated or rewritten. The one additive schema migration is server-side only.
- Serialize the collector's own history/live Arabicss requests to avoid overlapping requests on the same PHP session. Native report requests are never cancelled, retried or delayed by the hook.
- Label source snapshots, source events, periodic transport checks and explicit pre-break readiness checks separately. A transport check with no recent page-source snapshot reports unknown, never cached readiness. The compatibility heartbeat is retained pending a separate end-to-end continuity migration; it is not a new business event.
- Server rollout separately makes accepted end/logout events idempotent before stateful break validation. This unsigned source must be signed by Mozilla; do not publish it as a signed update.
